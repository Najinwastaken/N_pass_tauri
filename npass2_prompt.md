# Проект N-Pass 2 — локальный менеджер паролей на Rust + Tauri

## Контекст

Я переписываю свой старый пет-проект N_pass (менеджер паролей на Python + PySide6, лежит в `D:\Py\New_Py\N_pass` — можно подглядывать туда за UX-решениями, но НЕ за архитектурой хранения). Старая версия хранила всё открытым текстом в SQLite — новая версия делается ради настоящей безопасности, маленького веса и изучения Rust.

**Важно про меня:** я учу Rust. Когда используешь нетривиальные вещи (lifetimes, Mutex, трейты, `?`-оператор, zeroize), коротко объясняй, что это и зачем — не превращай в лекцию, но и не генерируй молча. Я должен понимать свой код.

## Стек

- **Backend:** Rust, Tauri 2.
- **Frontend:** TypeScript + Vite + React. Без тяжёлых UI-библиотек — вся стилизация своим CSS (у меня свой дизайн, тёмная и светлая темы).
- **Крипто-крейты:** `argon2`, `chacha20poly1305` (XChaCha20-Poly1305), `zeroize`, `rand` (OsRng), `serde`/`serde_json`.
- **Без базы данных.** Хранилище — один зашифрованный файл на профиль (объём данных крошечный, SQL не нужен).

## Модель данных и безопасность (ядро проекта — менять только по согласованию)

### Модель профилей

Мультипользовательность без «аккаунтов»: один пользователь = один файл-хранилище в папке `vaults/` рядом с приложением (или в app data — обсудим). Никаких таблиц users, никаких логинов. Файл самодостаточен: его можно скопировать на другой ПК и открыть тем же мастер-паролем.

```
vaults/
├── Misha.npass
└── Katya.npass
```

### Формат файла `.npass` (версионируемый, спроектировать до кода)

```
[magic: "NPV1" — 4 байта]
[format_version: u8]
[kdf_params: m_cost u32 | t_cost u32 | p_cost u32]   ← хранятся в файле, чтобы можно было усиливать в будущем
[salt: 16 байт, случайная, своя у каждого файла]
[nonce: 24 байта, новый при КАЖДОМ сохранении]
[ciphertext: XChaCha20-Poly1305( plaintext=JSON всех записей, key, nonce, aad=весь заголовок )]
```

- **KDF:** Argon2id, стартовые параметры: m_cost = 64 MiB, t_cost = 3, p_cost = 2.
- **AEAD:** XChaCha20-Poly1305. Заголовок передаётся как AAD — подмена заголовка ломает расшифровку.
- **Проверка мастер-пароля = успешная расшифровка.** Пароль и его хеш нигде не хранятся.
- Внутри plaintext — JSON: `{ passwords: [...], cards: [...], notes: [...], keys: [...], settings: {...} }`.

### Правила обращения с секретами

1. Мастер-пароль и выведенный ключ живут только в Rust-части, обёрнуты в `Zeroizing`/`zeroize` и затираются при блокировке.
2. Во фронтенд (WebView) расшифрованные пароли попадают только точечно: по явному действию «показать» или «скопировать» — одна запись, а не весь список. Список отдаётся с масками вместо паролей.
3. Никаких секретов в localStorage/sessionStorage, в логах, в `println!`.
4. **Генерация паролей — только `OsRng`** (криптографический источник). Никогда не `rand::thread_rng` для секретов и тем более не «свой рандом».
5. Запись файла — атомарная: пишем во временный файл → `rename`. Перед перезаписью — бэкап предыдущей версии (`.npass.bak`).
6. Автоблокировка: по таймеру бездействия (настраиваемый, по умолчанию 10 мин) и по сворачиванию окна (настраиваемо) — ключ выкидывается из памяти, UI возвращается на экран разблокировки.
7. Копирование в буфер: через 30 секунд буфер очищается, но только если там всё ещё лежит то, что положили мы.
8. Tauri: строгий CSP, минимальный allowlist, никаких `dangerousRemoteUrl` и удалённого контента.

## Архитектура backend (src-tauri/src/)

```
main.rs        — точка входа, регистрация команд, setup
state.rs       — AppState: Mutex<Option<UnlockedVault>>, таймер автоблокировки
crypto.rs      — derive_key (Argon2id), encrypt / decrypt (XChaCha20-Poly1305), generate_password
vault.rs       — формат файла: parse/serialize заголовка, load/save, атомарная запись, бэкап
models.rs      — PasswordEntry, CardEntry, NoteEntry, KeyEntry, VaultData, Settings (serde)
commands/
  profiles.rs  — list_profiles, create_profile, delete_profile
  session.rs   — unlock, lock, автолок
  entries.rs   — CRUD для всех 4 типов записей + reorder (drag&drop)
  misc.rs      — generate_password, copy_secret (с автоочисткой), open_url, reveal_secret
```

Каждая мутация данных (add/edit/delete/reorder) сразу же сохраняет файл (перешифровка + атомарная запись). Записи идентифицируются по `id: Uuid` — не по совпадению полей (это был баг старой версии).

## UX-флоу

1. **Запуск:** папка vaults пуста → экран «Создать профиль». Есть профили → экран выбора: плитки с именами + «Новый профиль».
2. **Создание профиля:** имя + мастер-пароль + повтор + индикатор надёжности + предупреждение «пароль восстановить невозможно, запишите его».
3. **Разблокировка:** клик по профилю → одно поле пароля → внутри. Неверный пароль → shake-анимация поля.
4. **Главный экран:** боковое меню как в старой версии — Passwords / Passkeys / Credit Cards / Secure Notes / Pass. Generation / Settings + кнопка Lock. Тумблер тёмной/светлой темы.
5. **Забыл пароль:** данные не восстановить, интерфейс должен честно говорить об этом.

## Фирменные UX-фичи из старой версии (обязательно перенести)

Это мои авторские решения, они — идентичность приложения:

1. **Умный Ctrl+C:** курсор в поле, ничего не выделено → копируется всё содержимое поля; есть выделение → копируется выделение.
2. **Поле даты карты (MM/YY):** копирование по позиции курсора — курсор до `/` → копируется месяц, после → год.
3. **Номер карты** копируется без разделителей-дефисов.
4. **Поле URL:** в контекстном меню пункт «Open URL» — открывает ссылку в браузере (через Rust-сторону, `tauri-plugin-opener`).
5. **Shake-анимация** незаполненных обязательных полей при попытке сохранить (CSS-анимация).
6. **Echo mode:** пароли скрыты точками, кнопка-глаз показывает/скрывает per-поле.
7. **Drag&drop** переупорядочивание записей в списке с сохранением порядка.
8. **Генератор паролей:** слайдер длины (до 30+), тумблеры lowercase/uppercase/digits/symbols, автоперегенерация при изменении настроек, кнопка Copy.
9. Тёмная (dark-blue) и светлая темы. Кастомное безрамочное окно с перетаскиванием — как в старой версии (в Tauri: `decorations: false` + drag region).

## План работ (по майлстоунам, каждый — рабочее приложение)

- **M1 — ядро:** формат файла + crypto.rs + vault.rs + тесты (roundtrip: create→save→load→decrypt; неверный пароль → ошибка; повреждённый файл → ошибка). Без UI, можно проверять юнит-тестами.
- **M2 — минимальный продукт:** профили, создание/разблокировка/блокировка, CRUD паролей, генератор. Простой UI без вылизывания.
- **M3 — полный функционал:** карты, заметки, ключи, drag&drop, умное копирование, автолок, автоочистка буфера, Open URL.
- **M4 — полировка:** темы, анимации, безрамочное окно, индикатор надёжности пароля, настройки, иконка, сборка релиза (`tauri build`), проверка веса.

Идём строго по порядку. M1 покрыть тестами обязательно — это единственная часть, где ошибка фатальна.
